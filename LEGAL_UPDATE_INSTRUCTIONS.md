# Legal Pages Update Instructions — komalkids.com

**Date:** April 14, 2026
**Triggered by:** App Store compliance audit of iOS app v-current
**Pages affected:** Privacy Policy, Terms of Service

## Privacy Policy (komalkids.com/privacy-policy)

### 1. Remove AdMob references

The policy mentions "Google AdMob serves child-directed ads" but the iOS app has zero ad SDK. No ads are shown.

**Find and remove** all mentions of:
- Google AdMob
- "child-directed ads"
- "advertising" as a data-sharing partner

If ads are planned for a future version, add this section back only when the SDK is actually shipped.

### 2. Replace "Supabase" with "Firebase / Google Cloud"

The policy says data is stored in "Supabase cloud databases and local IndexedDB storage." The iOS app uses Firebase Auth + Cloud Firestore + device Keychain. "IndexedDB" is a web-only API and does not apply to mobile.

**Replace:**
> Supabase cloud databases and local IndexedDB storage

**With:**
> Google Firebase (Authentication, Cloud Firestore) for cloud storage, and on-device encrypted storage (iOS Keychain) for local data.

If a web version also exists and uses Supabase/IndexedDB, list both platforms separately.

### 3. Add Google Gemini API as a third-party data processor

Child conversation text is sent to Google's Gemini API to generate character responses. This is not disclosed anywhere in the current policy.

**Add to the "Data Sharing / Third Parties" section:**

> **Google Gemini API (Generative AI):** When your child chats with a Komal buddy character, their messages are sent to Google's Gemini API to generate conversational responses. Messages are transmitted over HTTPS. We send the child's age group for age-appropriate filtering. We do not send names, device IDs, or other personally identifiable information. Google's data usage is governed by Google's Cloud Terms of Service.

### 4. Add Google Cloud Text-to-Speech as a third-party data processor

Character dialogue text is sent to Google Cloud TTS for voice synthesis. Not currently disclosed.

**Add to the "Data Sharing / Third Parties" section:**

> **Google Cloud Text-to-Speech:** Character dialogue is sent to Google's Text-to-Speech API to generate spoken audio. Only the text to be spoken, the selected voice, and language preference are transmitted. No child-identifiable data is included in these requests.

### 5. Add komalkids.com scan API to data disclosures

URLs visited by the child are sent to the Komal backend for safety classification. This should be explicitly listed.

**Add to the "Data Sharing / Third Parties" section:**

> **Komal Content Safety API (komalkids.com):** URLs visited within the in-app browser are sent to our own backend service for content safety classification. The URL and optional search query context are transmitted over HTTPS with certificate pinning. Results determine whether content is safe for the child's age group.

### 7. Update the "Data Retention" section

Add specifics that match iOS implementation:

> - **Eye tracking summaries:** Stored on-device only with full file encryption. Deleted after 90 days. Never uploaded to cloud.
> - **Browsing history:** Stored in Firestore under the user's account. Deleted upon account deletion.
> - **Chat conversation metadata:** Session-level metadata (timestamps, character used) synced to Firestore. Full chat transcripts are NOT stored.
> - **SEL assessment scores:** Domain scores and session records stored in Firestore. Deleted upon account deletion.
> - **Content filter preferences:** Stored in device Keychain (encrypted). Cleared on account deletion or app uninstall.
